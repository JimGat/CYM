## Retained fixes and corrections

- WiFi Scan & Attack uses `(live_height - 116) / 25`, minimum one row: eight
  at 240x320, four at 320x240, fourteen at 320x480 and eight at 480x320.
  Pagination Next/Prev remains separate from the floating action. Selection
  restoration and refreshed-results page clamping retain their existing logic.
- Wallpaper cover zoom uses actual asset width/height and live display size,
  rounded upward, never scaling down. Extra image area is clipped; it no longer
  leaves bare margins on 3.5-inch displays.
- Clock Mode card fits live screen minus 24 pixels, capped at 280x250, with
  vertical scrolling. Every action including Cancel is reachable; they need not
  be simultaneously visible. Classic and Modern retain their distinct return routes.
- CC1101 HW Test card scrolls vertically to the calibration controls. The
  existing Test/Set Offset/CAL TX actions and safety behavior are unchanged.
- WiFi menu scrolls vertically. Installed LVGL testing reproduced a centered
  wrapped-track bug in the original patch: the first row could remain above
  scroll zero. Only this menu's track alignment changes to START, preserving
  horizontal centering and making FIRST and LAST rows fully reachable.
- The floating **ATK** button invokes `wifi_scan_next_btn_cb` ->
  `show_attack_tiles_screen`: it opens attack selection and does not itself
  launch RF. Pagination Next/Prev and other Next labels are unchanged.

## Software evidence, cost and limits

Evidence on ESP32-Dev is under
`/home/dev/projects/cym-layout-041-implementation/`. The focused harness extracts
actual production constructors, pagination, checkbox callback, floating-button
constructor and Classic/Modern dispatcher; it executes the installed LVGL with
SDK/radio/unrelated endpoints mocked. It covers both layouts, all four rotations,
240x320/320x240/320x480/480x320, bounded cards, FIRST/LAST reachability, populated
HW Test labels, actual pointer scroll/release cancellation, empty/partial/full/
last pages, result refresh and independent selections across pages. Native
geometry/pointer checks are not physical touch or RF qualification.

Final software gates passed: 756 tests passed with one explicit private-capture
skip, 1001 focused native checks passed, and all nine guarded builds and 36
packaged artifacts passed validation. Exact source hashes and outcomes are
recorded in the integration evidence `final-verification.json`.

There is measurable cost, not a zero-overhead claim. Seven alternating native
baseline/candidate samples (30 WiFi menu construct + forced-render iterations
per sample) measured median increases of about 15-18 microseconds at 240x320,
12-17 microseconds at 320x240, 1.24-1.25 milliseconds at 320x480 (about 165-167%),
and 0.30 milliseconds at 480x320 (about 19%). This is x86 software rendering,
not panel-transfer or embedded timing; larger covered wallpaper is real work.
Native allocator tracking measured roughly 21 KB for eight scan rows, 9.5 KB
for four and 37 KB for fourteen; the tall page adds roughly 15-16 KB versus
its prior eight rows. These are native malloc class sizes, not ESP32 heap or
capability measurements. Per-board linked maps are separate static evidence.
No intentional sleep, blocking wait or input throttle is introduced. Actual
keyboard/menu latency remains hardware-unmeasured.

## Preservation and pending physical regression checklist

- Preserve v3.0.40 FSD lifecycle/cancellation, v3.0.39 RF-HAT ownership and
  lifecycle safeguards; UART remains primary with USB/debug-OFF silence.
- Preserve accepted panel/touch/color/calibration transforms, board pins,
  partition/NVS layouts, SD 20 MHz and intentional background operations.
- On each actual board, both layouts and supported orientations: verify WiFi
  FIRST/LAST rows with finger scrolling; a scroll release must not activate a
  tile/action. Check wallpaper edges and ordinary menu/keyboard responsiveness.
- Clock: scroll to all four actions including Cancel, Back/Home and reentry;
  confirm the correct Classic/Modern return destination without stuck presses.
- HW Test: ensure populated result and calibration controls remain reachable.
  This integration performed no serial actions, hardware Test, CAL TX or RF test.
- Measure hardware internal/DMA free/minimum/largest blocks, PSRAM, stack
  high-water, fragmentation, repeated entry/exit and render/transfer latency
  before asserting hardware memory/performance acceptance. Linked/static
  budgets cannot establish those runtime properties.
- PN532 remains deferred, root cause unproven, and is first to revisit in the
  canonical backlog. Power Mode and tile proportionality are out of scope.

Hardware acceptance remains pending; no hardware was flashed during integration.
