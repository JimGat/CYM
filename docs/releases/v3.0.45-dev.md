# Development v3.0.45 candidate — Package B softAP lifecycle

Original Package B author and co-developer: @birolt29
<birolt29@users.noreply.github.com>. JimGat integration corrections are separate
from the retained contributor patch. Parent independently reviews and publishes;
this working candidate is not a Stable promotion.

Portal/Rogue running views expose Suspend AP / Resume AP. Initial start, suspend,
resume and screen-exit attack teardown use a lazy internal 4096-byte-stack worker,
not LVGL. Admission success means queued, not active. Busy, idle, starting,
held, active, failed and uncertain-release states are distinct. Repeated taps
cannot queue overlapping transitions. Home/Back invalidates resume eligibility.
A failed/uncertain cleanup retains ownership; retry stop before replacement.

The shared Evil Twin API uses the same lifecycle, but no new Evil Twin
running-view button or redesign is included. Packages D/E/F/H are deferred.
There is no global TX-off promise: the owned associated deauth task is stopped
on suspend and recreated from the captured target selection on explicit resume.
The STA interface is restored to STA-only after successful owned teardown;
other radios and utility workflows are not advertised as RF-silent.

Integration corrections validate immutable inputs before radio effects, snapshot
selected targets, reject queue overflow/invalid-state changes atomically, retain
owner lifetime across resume, reject stale work before primitives, and reconcile
late successful starts before releasing the physical reservation. Clock and file
server reserve the shared AP/STA before pending startup. No callback is not
permission. Checked HTTP registration, DNS bind/task readiness, single FD lifetime
ownership, bounded stop acknowledgement and retained handles prevent false release.
UI timers are reclaimed on DELETE and route/page cleanup.

Tests distinguish pure decision helpers, production worker/SDK-boundary mocks,
and installed LVGL control geometry/callback tests. A failed compilation or random
crash is never a semantic mutant kill. See tests/README.md and the private
ESP32-Dev cycle evidence for actual executions and outstanding gates.

Author-reported NM phone/scanner observations have no attached logs: they are
observations, not independently reviewable evidence or a stop-latency measurement.
No physical flash, RF capture, device heap fragmentation, stack-high-water,
watchdog/responsiveness or independent RF acceptance was performed here. Board
compilation and host mocks do not substitute for these measurements. Existing
pins, display/stack buffers, partitions, SD/NVS, USB/GPS/time arbitration,
Package C HAT TX/screenshot, G ownership and Patch24 behavior remain protected.

cyd-2432s028, cyd-2432s028-l, hackerbox-cyd, hosyond-s3-35, pancake-c5,
ws-s3-5b. Build/package acceptance is recorded in final-verification.json outside
