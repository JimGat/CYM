## Allocation and runtime map

- Existing LVGL/display buffers, DMA routing/alignment and target allocation
  capabilities are unchanged. Neither native malloc nor static linking proves
  DMA largest-contiguous-block or runtime internal headroom.
- WiFi rows are allocated by LVGL during page reconstruction and released by
  the existing `lv_obj_clean(scan_list)` lifecycle; page size is 4/8/14 for the
  tested screen heights. Selection tables, scan buffers and stop hooks are unchanged.
- Clock/HW Test/WiFi scrolling changes LVGL object styles/scroll state, not task
  stacks or worker lifetime. Popup close and existing screen teardown own widgets.
- Scaled wallpaper uses the existing asset; software-render/transform scratch and
  work may grow. Asset storage is not an estimate of transient render heap.
- Existing WiFi/network/service tasks, stacks/TCBs and service-heap allocations
  are not resized by this patch. Their simultaneous lifetimes and high-water
  margins still need board-specific runtime capture.
- Native measured rows: about 9.5 KB (four), 21 KB (eight), 37 KB (fourteen);
  native x86 allocator classes are not ESP32 internal/PSRAM placement evidence.
- Hardware internal/DMA free/minimum/largest blocks, PSRAM free/minimum, stack
  high-water, fragmentation and physical render/transfer timing: UNMEASURED here.
- App/flash/partition size and remaining partition margins are checked independently
  for every exact board by the nine-profile package verifier.
